# 短任务模板

复制到实际任务，删除说明和不适用字段；禁止把占位符当默认决策。普通小修复可
直接写在现有任务/PR 中。任务是行动边界，不是把所有规范再抄一遍。
操作方式见 [推进指南](../OPERATING_GUIDE.md)，执行规则见 [SOP](SOP.md)。

## 目的与边界

要解决的问题/决定：用一句话说明这项工作怎样推进 PROJECT_RECORD 的目标。
当前依据与为何现在做：链接已有证据；若尚无依据，标为探索假设。
模式：治理 / 工程 / 离线分析 / 原条件复现 / 探索实验 / 确认实验。
父提交与任务负责人：实际 SHA；当前负责的人或 agent。
允许改动、保持不变、明确不做的事：只填影响本任务的边界。
授权来源：用户原话或可追溯任务；记录是否覆盖物理执行及具体预算。

## 决策依据（涉及选型、参数或科学问题时填写）

选择及状态：工程起点 / 待验证候选 / 已据证据选择。
相关替代方案与取舍：说明为什么采用当前方案；无需无限横向调研。
关键参数依据：实际需求 / 上游协议 / 有限证据 / 工程假设；不混写。
比较条件与缺口：原条件和本平台有哪些不同，哪些尚未消除。
会改变决定的结果：支持、反对或无法判断时分别下一步是什么。

## 执行与完成

最小步骤、入口与产物：给出可执行命令或具体编辑位置；先检查所需环境。
完成依据：与问题相称的验收；没有性能变化时不发明性能门槛。
相关检查与审查：引用现有命令/规则，不复制整份 SOP。
停止或调整条件：包括必要的资源上限、输入变化、无效结果的处理。
实验另引用唯一前瞻协议：假设/对照、变量、指标、样本设计、预算、失败继续或
停止规则、raw 位置和分析器；用 [实验记录模板](../EXPERIMENT_TEMPLATE.md) 补齐，
同一参数只在协议定义一次。

## 交接（持续更新本节，已封存结果另行追加）

当前分支/SHA/dirty：实查结果，不写“最新版本”。
已完成及证据：链接结果和检查记录；区分 PASS、FAIL、INVALID、NOT_RUN。
尚未决定/被阻塞：具体缺口及其影响；没有就写无。
下一条动作、预期产物、到哪里停止：接手者不需猜测。
关闭条件：本任务何时结束；新研究方向另立任务，不无限续写。
